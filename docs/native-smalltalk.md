# Native Smalltalk owners

The Symmetric Smalltalk personality is the largest owner in the registry and the one that grows
under every imported application. `docs/ownership.md` names each of its owners in one paragraph;
this file holds their full contracts, invariant by invariant, and the three tiers ADR 0093 fixes for
how the personality may grow. The registry row is authoritative for WHO owns a concern; the contract
here is authoritative for WHAT that owner promises. Nothing here is a second owner.

## The three tiers

ADR 0093 names the tiers the standard image already has and the growth rule each one obeys:

| Tier | What it is | Where | Grows only when |
| --- | --- | --- | --- |
| 1. Kernel primitives | the `smalltalk-kernel-primitive/v1` operations (`SMALLTALK_PRIMITIVE_NAMES`): identity, allocation, slot and indexed access, Integer arithmetic and ordering, hashing/equality, interning, Character scalars, control transfer, super sends | `src/language/smalltalk-primitives*.js`, registered by the composition root | the semantic is host-sensitive and cannot be written as ordinary Smalltalk over existing primitives, AND a real consumer reaches it; the sorted name guard, a recovery sweep and lane conformance land with it; a primitive never encodes a Cuis class or selector policy |
| 2. Native library | ordinary classes and methods written in Smalltalk over tier 1 and published through the ordinary namespace: Association, OrderedCollection, Dictionary protocol, Set, ReadStream/WriteStream, Character classification, Interval, Point, Array2D, TextModel | `src/language/smalltalk-library.js` and the per-class owners (`smalltalk-set.js`, `smalltalk-write-stream.js`, …), sequenced by `smalltalk-standard-image.js` | a real consumer NAMED the class or selector, with exactly the protocol that consumer exercised (a "measured surface"); semantics are anchored to a recorded real-Cuis oracle when the consumer is imported Cuis code; library composes library (`collect:` over `do:`), never a primitive per class, never a foreign-dialect compatibility class |
| 3. Cuis correspondence and translation | the import adapter's closed identity -> native-class table and its token-level idiom plan | `src/language/cuis-native-import.js` | a frozen real-Cuis measurement for the exact POSITION (superclass or method target) or the exact idiom; keyed by complete semantic identity, never by name; each entry names the milestone or Bead that forced it; entries are never added or removed for convenience |

A class that reaches the image through tier 3 is still a tier 2 class: the correspondence says which
native class a Cuis identity denotes; the native class owns its protocol and grows by tier 2's rule.
The `docs/domain-agent-rules.md` invariants apply across all three tiers and are not restated here.

## The class builder and the personality

**Registry row:** Symmetric Smalltalk language semantics. **Owner:** Symmetric Smalltalk personality. **Location/status:** `src/language/`.

Owns syntax, lookup, class/kernel/library semantics and language-specific compilation policy. Character syntax and runtime personality are one such semantic (ADR 0090): the tokenizer/parser/compiler own `$x`, `smalltalk-character.js` owns canonical image-local Character objects, and native `Text>>at:` delegates to the same interner; Character is neither Text nor Integer and adds no generic Value kind or `lagrange-code` operation. The class builder owns native class declaration -> complete instance Shape: callers provide ordered local instance-variable names, while `ensureClassFromDeclaration` assigns initial stable slot ids from defining native Class identity + declared name, preserves inherited ids/order, and delegates immutable Shape/Class admission to the existing ensure owners. It also owns native logical method position (Class/Metaclass + selector), immutable method-revision identity from normalized native semantics/lane/captures, exact replay, explicit `reconcileMethods` evolution and publication through the existing MethodDictionary expected-version CAS. It is therefore also THE EXECUTION-LANE OWNER for a method position (bead lagrange-images-it3): it publishes `metadata: {smalltalk: 'method', selector, lane}` on every method Block it installs, and it is the one locus that reads that fact back. The rule is scoped as narrowly as the question that produced it, and `installMethods` takes its lane from exactly three places: a NAMED lane is used as named, because an internal caller has decided and this owner does not overrule it; no lane and no observed revision is `neutral`, the definition/creation default, unchanged; no lane and an OBSERVED revision (`expectedCurrent`) is THAT REVISION'S lane. Since the public E3 seam names no lane at all, only the third case is reachable from a consumer — so from a consumer's side, replacing what a native method MEANS is never also a migration of how it RUNS. This is a rule about NATIVE methods, not about imported ones: a native method replacement preserves the method's existing native execution policy, whatever produced it, and that imported Cuis material is the first consumer to notice is a fact about who asked. Definition is untouched: `expectedCurrent` is refused on the add-only path, so there is never an observed revision there to preserve a lane from. The lane is taken from the OBSERVED immutable revision and never from the current binding, so preservation cannot refresh half of the caller's assumption while still enforcing the other half. There is NO FALLBACK in either direction: a replacement the observed lane cannot compile fails and the observed revision stays current, because changing a method's execution representation is a migration, not part of replacing its semantics. The whole small method-Block contract is validated rather than `lane` alone — an absent record, one not marked as an ordinary native method, one naming a DIFFERENT selector, and one recording no known lane are all `SmalltalkMethodLaneError`, never a silent default to neutral — because "this ref is bound at the position" is not yet "this ref is a native method revision of THIS position"; identity is deliberately not reconstructed from ids (that would make a legitimately revised method unreplaceable) and the ref's own unpinned/local shape is not rechecked, because `readExpectedCurrentBindings` already owns that rule. A guarded batch whose observed revisions sit in different lanes is also refused, since one `installMethods` call derives revision identity, exact replay and code production from a single lane. Reading the lane back here is this owner reading its own record, NOT a CodeArtifact or executable-representation decode — which is precisely why the authorized replacement seam may not answer the same question (ADR 0087/0088). An UNGUARDED write's lost CAS winners are classified once here: identical semantics converge; divergent semantics are a Smalltalk method conflict; no backend conflict or overwrite escapes. `defineMethods` remains add-only. It also owns the OPTIMISTIC-CONCURRENCY PRECONDITION on that position (bead lagrange-images-qax slice C1): a `reconcileMethods` method entry may carry `expectedCurrent`, the binding the caller OBSERVED, and this owner requires it to still be current at plan time AND again at every retry boundary before the position advances. Guarded and unguarded lost-CAS policy differ deliberately, because a whole-dictionary CAS and a selector-position precondition are different granularities: unguarded is ADR 0086 decision 4 exactly as written — classify the winner once, converge or conflict, never retry — while a guarded write whose own position is untouched REBASES (reread through the same read-for-update, lay only this operation's published Blocks over the freshly read bindings) and retries, bounded, so an unrelated selector's winner is neither reported as staleness nor overwritten from a stale planning snapshot. The precondition is evaluated BEFORE ADR 0086 exact-replay convergence, so an external replacement that happens to mean what the caller wanted is still `SmalltalkStaleMethodPositionError` while a genuine replay against the observed state stays write-free; the expectation is never refreshed from later-observed state, and a position that has moved fails immediately with its winner intact. The stale error names only the position the caller supplied — no current Block ref, no MethodDictionary or backend version, no `cause` — and exhausting the rebase budget is its own `SmalltalkMethodDictionaryContentionError`, which may be claimed ONLY after the expectation has been re-asserted at that boundary too: every lost CAS including the LAST one rereads and re-asserts first, so a position that moved on the final attempt is stale rather than contention, and contention means what it says — the position is unchanged and the dictionary is simply being written faster than this operation can rebase. That error does NOT claim an empty write, because the replacement's immutable material is published before the final CAS — so no backend `VersionConflictError` escapes on either path. Publication order is stated honestly rather than promised away: compilation admits the immutable revision material BEFORE the final CAS, so a stale outcome detected at a retry boundary can leave an addressable, non-current revision in the image. The load-bearing invariant is that a failed, stale or uncompilable replacement never makes its revision CURRENT — not that it writes nothing, which is true only of a plan-time refusal. All of this is TRUSTED INTERNAL semantics with no authority of its own: an authorized wrapper may supply an observation it verified and adds no concurrency decision, because every one of them is here. Importers never choose native slot or method revision identity. The subclass-registry locus (`smalltalk-subclasses.js`) owns append-only direct-subclass membership, record validation and its owner-local conflict type. Native Integer semantics, including its printing protocol (`printOn:base:`, which writes to its argument through ordinary sends and composes existing arithmetic and the byte/text conversion rather than adding a primitive), stay in `smalltalk-integer.js`; the standard image only sequences the printing stage after the global namespace exists, because its source names `Array` and `ByteArray`. The image-resident library owners (`smalltalk-library.js`, `smalltalk-write-stream.js`) own ordinary native classes written in Smalltalk over the kernel protocols and published as ordinary globals; a class lands here because a real consumer named it, with exactly the protocol that consumer exercises, and never as a foreign-dialect compatibility class. A stream owner also owns how it CONSTRUCTS its result: `smalltalk-write-stream.js` builds `contents` from what was written, preserving the backing's class, rather than asking the backing to allocate one — which is what lets a Value-backed stream answer at all, since a native text Value is not allocatable — `WriteStream` is native library protocol usable by any native code, not a Cuis shim, and the Cuis import adapter resolves the name through the ordinary global namespace with no knowledge of it. The class builder owns THE CURRENT BINDING — what Block is bound at `{Class, selector}` right now — as ONE reader (`currentSelectorBindings`), because it is one question. ADR 0049 makes two MethodDictionary representations legal at once, and every caller goes through that reader: the caller-facing published protocol (`selectorBindings`, exposed as `methodBindings`/`methodBlockRef`, which the authorized browse seam is built on) and the installer's read-for-update (`readMethodBindings`, used before planning a definition, to classify a lost dictionary CAS and to rebase a guarded write onto an unrelated winner). "Which selectors does this class implement", "which Block does this selector bind" and "what am I about to replace" therefore cannot drift apart, and BOTH representations apply the same corruption rules — non-empty selector, unpinned Block ref, local to the image, no duplicate selector, dangling Shape is an error — rather than one rule set per representation. The read-for-update adds only write-path facts (the seal check and the representation flags), never a second notion of what is bound. It answers for that Behavior ALONE; what a SEND resolves to across a superclass chain stays owned by `smalltalk-lookup.js`, whose relation to this reader differs by representation: for a HASHED dictionary dispatch validates the whole table and refuses together with this reader, while for a LEGACY one it validates only the slot for the selector being sent — it answers one send rather than describing a class — so it can still resolve a good selector in a dictionary this reader refuses whole. The invariant is that the current-binding reader is never LAXER than dispatch, not that they refuse identically. Two further readers of the same records remain separate implementations, named here rather than left to be discovered: the migration reader (`smalltalk-method-dictionary-migration.js`) and the legacy-shape validator `isLegacyMethodDictionary` (`smalltalk-kernel.js`). Their rules now match this reader's; unifying the implementations is bead lagrange-images-jtz.6.

## The authorized browsing seam

**Registry row:** Authorized native Symmetric Smalltalk class/method description and version-aware read for update. **Owner:** Native Smalltalk browsing seam. **Location/status:** current (ADR 0087 corrected by bead lagrange-images-31l after Object Environment reopened GitHub #218): `src/language/smalltalk-browse.js`; public method-position vocabulary: `src/language/smalltalk-method-position-resource.js`.

Owns ONE thing: WHICH native Smalltalk facts are publicly describable, in what canonical origin-neutral shape, and under which authority. It decides no graph fact and writes nothing. Every fact is composed from its existing owner — Class/Metaclass identity, superclass, method-dictionary edge and instance-shape edge from `readBehavior`; the image's `nil` terminator and Metaclass identity from `findSmalltalkKernel`; selector -> Block bindings from the class builder's `methodBindings`; declared layout from the instance Shape; Class object authority naming from `authority/object-resource.js`; and the pure, injective logical-position operation/resource naming from `smalltalk-method-position-resource.js`. `smalltalk-class-description/v1` = `{format, class, name, side, superclass, classSide, layout, selectors, provenance}` and `smalltalk-method-description/v1` = `{format, class, side, selector, method, source, provenance}`; storage layout, backend versions and Cuis identity never escape. Class browsing requires Class `object/read`. Both `authorizedDescribeSmalltalkMethod` and `authorizedReadSmalltalkMethodForUpdate` use ONE `authorizedMethodPosition` path: validate input, require Class `object/read`, require exact `smalltalk-method/read` on `{imageId, Class/Metaclass, selector}`, then and only then resolve existence/current binding and read the Block. The method-position resource is nameable from public semantic facts without graph access or existence disclosure and remains stable across immutable revisions, so first read, successful-replacement reread and stale reread use the same authority. It is exact to image/class/side/selector and is NOT `object/read` on the resulting Block: direct Block inspection and historical/superseded revisions still require their own object grant. Class read yields selector names but never a method; position read is not transitive Class authority; refs and tokens confer zero authority. The writer-facing read answers frozen `{descriptor, versionToken}` from the same one resolution and asserts no write authority. The opaque selector-position token remains owned by `smalltalk-method-position-token.js` and scoped to the observed current binding; it is concurrency data, not authority. `source` and `provenance` remain `null`; browsing remains origin-neutral and read-only.

## The authorized replacement seam

**Registry row:** Authorized native Symmetric Smalltalk method REPLACEMENT. **Owner:** Native Smalltalk method-replacement seam. **Location/status:** current (ADR 0088, bead lagrange-images-qax slice C2, Object Environment E3, GitHub #218): `src/language/smalltalk-authorized-method-replacement.js`.

Owns `authorizedReplaceSmalltalkMethod({images, compilation, imageId, classRef, selector, source, expectedVersionToken, require})`, the ONE public operation that advances an EXISTING native method at `{Class/Metaclass, selector}` to explicitly supplied new source. It owns exactly six things and no more: caller-owned input validation; the token's syntax and scope for THIS `{image, class, selector}`; the authority demand and its ORDER relative to every graph read; the current-position resolution that bridges a token to an expected binding; the pre-compilation admission of that expectation; and the public result/error contract. It owns NO concurrency semantics: what "still current" means in flight, the unrelated-selector CAS rebase, the bounded contention budget, immutable revision publication and source lowering all stay at the class builder and the from-source compiler owner, reached by handing `reconcileMethodsFromSource` the caller's ORIGINAL observation as `expectedCurrent`. The current binding is read through the ONE current-binding reader (`methodBlockRef`); this module decodes no MethodDictionary bucket, Shape or backend `_version`, opens no dictionary, and performs no write, retry or rebase of its own. ORDER IS THE CONTRACT: validate caller shape, validate the token's scope, require `object/write` on the declaring Class/Metaclass, resolve the current binding, admit the token against it, refuse a stale position BEFORE any compilation is invoked, then call the from-source owner. AUTHORITY is exactly ONE `object/write` on the Class/Metaclass, because a replacement mutates that Behavior's selector-BINDING state; it is NOT demanded on the previously bound Block, which is immutable revision material (ADR 0086 decision 1) and is not what changes, and it is never inferred from a class read, a Block read, possession of refs, Project membership or possession of the token — A TOKEN CONFERS ZERO AUTHORITY. Authorization strictly precedes existence disclosure, so a denied caller cannot distinguish an implemented selector, an unimplemented one and a missing class: all three are `AuthorityError`. The pre-compilation admission is not a second authority on staleness — the same observation is passed to C1, which re-asserts it at plan time and at every rebase boundary and whose verdict is final; it exists so that a stale caller gets the stale verdict instead of a compiler diagnostic, and so that inadmissible source is never compiled. The caller's token is never replaced by a fresh read. NO EXECUTION LANE IS PUBLISHED AND NONE IS CHOSEN HERE: a `lane` parameter would publish a compiler knob on a seam that exposes no compiler, and discovering the bound method's lane HERE would mean decoding its Block's code artifact, which ADR 0087 rejected. This module therefore does not know and must not learn how the method it replaces executes; what happens to the execution lane is the class builder's decision (bead lagrange-images-it3, ADR 0088 decision 6 as amended): because this seam names no lane, its replacements are compiled in the lane of the revision the caller OBSERVED, so replacing what a native method MEANS is never also a migration of how it RUNS. A structural proof keeps this module free of any lane name, Block/CodeArtifact read or representation branch, and `SmalltalkMethodLaneError` passes through unrestated because it already names only the caller's own position. SOURCE IS NOT PERSISTED: ADR 0087's `source: null` stays truthful after a successful replacement (#218 point 5). The receipt is frozen `{replaced: true}` and deliberately carries no new Block ref, descriptor, token or source, because the consumer has committed to a fresh authorized reread as displayed truth (#218 point 4). The public taxonomy is discriminated by `error.name`, the only discriminator available through `src/portable-runtime.js`: `SmalltalkMethodReplacementInputError` (malformed caller input — its own class precisely because the native semantic compiler also rejects bad SOURCE with a bare `TypeError`), `SmalltalkMethodPositionTokenError` (malformed or wrong-scope token, refused rather than reinterpreted), `AuthorityError`, `SmalltalkMethodTargetError` (after authorization: no such native method position; it names only the caller's own position and forwards no owner diagnostic, because those name the class's MethodDictionary record), the class builder's own `SmalltalkStaleMethodPositionError`, `SmalltalkMethodReplacementContentionError` (transient; the position is unchanged and was not advanced, covering BOTH an exhausted rebase budget and a dictionary sealed for migration — a position-scoped restatement of the owner's dictionary-scoped outcome, which would otherwise publish storage identity), and otherwise the native compiler/source owner's own rejection — only the class builder's own semantic refusals are restated, so a host or transport failure of the binding read propagates as raised rather than becoming a false "this method position is gone". No backend `VersionConflictError` escapes raw or as a `cause`, and no MethodDictionary ref, representation or version, backend version, winning Block ref or replacement token appears in any refusal. An ABSENT selector is stale, not a fresh definition — the same rule C1 applies — because E3 adds no method. NOT owned here and deliberately absent: method addition, removal, class editing, batch editing, durable method source, protocol/category, Cuis provenance, a public compiler and a public reconciliation API. PUBLICATION: `authorizedReplaceSmalltalkMethod` is re-exported BY NAME from `src/runtime.js` and `src/portable-runtime.js` and this module is deliberately NOT added to `src/language/index.js`, whose `export *` would publish the module's internal error classes and any later helper on the package's `.` and `./language` surfaces.

## The Cuis native-import adapter

**Registry row:** Cuis semantic facts -> native Smalltalk calls. **Owner:** Cuis native-import personality/adapter. **Location/status:** current M1/M2 + ADR 0086/0091: `src/language/cuis-native-import.js`.

Owns translation only: preflights canonical v2 schema/identity/dependency topology, owns the ONE seam that corresponds a complete Cuis semantic class identity to an already-proven native class, keyed by full semantic identity and never by class name, with no fallback and no caller-supplied alias, and with each entry declared for the POSITION it is proved in — today exactly `cuis-class/Cuis-Base/Object` as a SUPERCLASS (the M1 structural root; refused as a method target, because installing a package selector on the native image root is a claim no consumer has made) and `cuis-class/Cuis-Base/Integer` as an instance-side METHOD TARGET (the class ordinary native integers dispatch through, so a package's extension method installed there is reached by real receivers; refused as a superclass, because an integer's dispatch class is fixed by its kind). A manifest may not also DECLARE a mapped identity: one semantic identity has one authority; orders declarations and calls `ensureClassFromDeclaration`; for methods it validates canonical target/side/identity, translates ordinary Cuis unary/binary/keyword headers and the Cuis implicit-receiver return rule to the existing class-scoped Block-source input, and calls `reconcileMethodsFromSource` on the resolved native Class/Metaclass in the WASM lane. It also owns the oracle-backed method-body replacement plan: collect every replacement against one original token stream, then apply it right-to-left once. Today that plan translates the distinct legacy-assignment token to canonical `:=` and three closed, oracle-backed idioms: `String new` to an empty native Text value, `UnicodeString writeStream` to the parenthesized ordinary native construction `(WriteStream on: '')`, and exact `UnicodeString streamContents: [literalBlock]` to the native semantic locator `Text streamContents:` while leaving the Block untouched. The tokenizer owns the measured distinction between a legacy arrow and legal underscore identifier forms; the native parser refuses the arrow token directly, while this adapter translates it and never validates a target, resolves an RHS or creates a binding. Idioms are matched on tokens so literals and comments are untouched, begin only where the parser can begin an expression, and do not fire where the package binds or declares the name itself or on a cascade; the keyword idiom additionally requires one literal Block and a complete expression boundary, never a longer selector chain. Each is justified by a recorded real-Cuis measurement of its exact covered role. ADR 0091 keeps all block evaluation, accumulation, result and error semantics in the native Text/WriteStream owner; the adapter translates only the foreign receiver name and selector. Keying an idiom by source token rather than complete semantic identity is a deliberate asymmetry with the class-mapping table: a name inside method source carries no package attribution, so narrowness plus exclusions stand in for identity. These are translations, never class mappings: the adapter publishes no String/UnicodeString global, maps no Cuis class identity through them, invents no Utf8EncodedWriteStream, and changes no native Text, WriteStream or assignment semantics; every other use stays unbound, and direct native `_` stays refused. It also owns the caller-declared import scope over the UNMODIFIED canonical manifest — which declarations one import covers — because a real package is imported progressively: manifest-wide schema, canonical identity and uniqueness stay checked for every declaration, while native target legality and source translation apply to the covered subset. An omitted required superclass, an out-of-scope method target and an unsupported semantic INSIDE the scope are explicit refusals; the adapter never widens the scope silently and never skips a covered declaration as though it had succeeded. Omitting the scope imports the whole manifest. Native declaration/body/compiler/method-position/revision identity/history/admission legality remains solely in existing owners; the adapter compares no source and keeps no previous-source/revision state. Returns transient semantic-identity/ref associations; owns no durable side table, Class, Metaclass, Shape, slot id, object, allocation, method dictionary, Project, storage or fallback semantics.

## Reading rule

The full contracts above were moved verbatim from `docs/ownership.md` (ADR 0093) so the registry
stays a one-paragraph-per-owner map. When an owner's contract changes, change it here and keep the
registry paragraph a faithful summary; the tests that pin these contracts are named in each
paragraph and in `docs/seams.md`.
