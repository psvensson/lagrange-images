# ADR 0096: Durable native method source, category/provenance association, and Cuis post-load initializers

Status: implemented
Proven by: test/smalltalk-authorized-browse.test.js, test/smalltalk-builder-recovery.test.js, test/cuis-native-import.test.js, test/smalltalk-msgpack-authentic.test.js

## Context

1. **Durable native method source and class/method category/provenance (`lagrange-images-jtz.1`).** Under ADR 0087 decision 6, `authorizedDescribeSmalltalkClass` and `authorizedDescribeSmalltalkMethod` reported `source: null` and `provenance: null` because `src/language/smalltalk-class-builder.js` persisted only `<methodId>:semantic` and the method Block without retaining `<methodId>:source` or normalized `{package, category, file}` provenance metadata. Meanwhile, ADR 0087 explicitly rejected walking `CodeArtifact.derivedFrom` inside `src/language/smalltalk-browse.js` (which would create a second `CodeArtifact` decoder), and ADR 0088 required unretained definitions and replacements to keep reporting `source: null` and `provenance: null`.
2. **Cuis post-load class initialization.** Real Cuis packages (such as YAXO `XMLTokenizer initialize!`) include top-level post-load class initialization chunks that initialize declared class variables after classes and methods are installed. Previously, callers importing such packages had to invoke `ClassName initialize` manually after `importCuisNativePackage`.

## Decision

1. **Class-builder-owned durable method source and class/method provenance (`<methodId>:source`, `methodSource`, `classProvenance`, `methodProvenance`).**
   - `defineMethods` and `reconcileMethods` in `src/language/smalltalk-class-builder.js` accept optional `source` text, `category` text, and `provenance` (`{package?, category?, file?}`) on each method descriptor. When `source` is provided (including via `retainSource: true` on `defineMethodsFromSource`, `reconcileMethodsFromSource`, `importCuisNativePackage`, or `authorizedImportCuisPackage`), `installMethods` persists a deterministic `<methodId>:source` `CodeArtifact` (`languageId: 'symmetric-smalltalk'`, `representation: 'symmetric-smalltalk/source-v0'`) before `<methodId>:semantic`, links `<methodId>:semantic`'s `derivedFrom` to `[objectRef(imageId, '<methodId>:source')]`, and includes `source` in revision identity (`methodRevisionId`) and convergence checks (`isSameInstalledMethod`).
   - `defineClass`, `ensureNamedClass`, `ensureClassFromDeclaration`, and `evolveSmalltalkClassShape` accept optional `provenance` (`{package?, category?, file?}`), persisting normalized `metadata.provenance` on the Class and Metaclass records and verifying it during idempotent rediscovery. Similarly, `installMethods` persists normalized `metadata.provenance` on the immutable method Block and includes it in `methodRevisionId` and `isSameInstalledMethod` (adding zero extra database records).
   - `src/language/smalltalk-class-builder.js` owns and exports `methodSource({images, imageId, blockRef, block?})`, `classProvenance({images, imageId, classRef, behavior?})`, and `methodProvenance({images, imageId, blockRef, block?})`, which return the retained source text or normalized `{package?, category?, file?}` provenance object, or `null` when absent.
   - `src/language/smalltalk-browse.js` calls `classProvenance` in `describeBehavior` and `methodSource` / `methodProvenance` in `authorizedMethodPosition` strictly after `object/read` on the Class/Metaclass (and `smalltalk-method/read` on the logical method position) have succeeded. It never walks `CodeArtifact.derivedFrom` or decodes executable representations itself.
   - Because `<methodId>:source` and `metadata.provenance` are keyed by the immutable revision Block (`blockRef.objectId`), an unretained method or an unretained replacement revision has neither `<revisionId>:source` nor `metadata.provenance` and truthfully reports `source: null` and `provenance: null` (never leaking stale source or category/provenance from an earlier revision).

2. **Explicit Cuis post-load class initializers (`extractCuisPackagePostLoadInitializers` and `postLoadInitializers`).**
   - `src/language/cuis-native-import.js` exports `extractCuisPackagePostLoadInitializers(packageName, pckSource)` to parse top-level post-load `<ClassName> initialize!` chunks from Cuis `.pck.st` chunk-format text into canonical `cuis-class/<packageName>/<ClassName>` identities while rejecting arbitrary DoIt expressions.
   - `planCuisNativeImport` and `importCuisNativePackage` (and `authorizedImportCuisPackage`) accept optional `postLoadInitializers` (on the manifest or options). Every entry must name an in-scope imported class (or `<ClassName> initialize`) that declares a covered class-side `initialize` method (`cuis-method/<pkg>/<Class>/class/initialize`); any other selector or expression is refused before the first native write with `CuisNativeImportError`.
   - Planned post-load initializers are ordered deterministically by package dependency topological order (`manifest.packages` `requires`) and class inheritance topological order (`plan.ordered`), and are dispatched as unary `initialize` sends to each resolved `classRef` after all classes, class-variable bindings, globals, and method groups have been installed.

## Consequences

- Callers that opt into `retainSource: true` (or supply `source` to `defineMethods` / `reconcileMethods`) get durable, restart-safe `symmetric-smalltalk/source-v0` method source visible through `authorizedDescribeSmalltalkMethod` and `authorizedReadSmalltalkMethodForUpdate` without turning `smalltalk-browse.js` into a `CodeArtifact` decoder.
- Existing callers and E1/E3 proofs that do not request `retainSource: true` continue to write zero extra artifacts and observe `source: null`.
- Cuis packages with `ClassName initialize!` post-load initializers can execute their class-side initializers deterministically as part of native import while arbitrary load-time DoIt expressions remain refused.
